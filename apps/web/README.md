# Blacksmith front end

React 19 and strict TypeScript, built with Vite and served by the web container.
It is one scrolling page with one functional surface, the workbench, wrapped in a
decorative WebGL2 scene. No scheduler feature lives here: the page reads
`GET /api/system` once and can send the simulation-only `POST /api/preflight`.

Use the [root workflow](../../README.md) and project-container tooling. Do not
install or run dependencies using host Node 14. OpenAPI types are generated by
the root build command.

## Layout

| Path                                         | Role                                                                                          |
| -------------------------------------------- | --------------------------------------------------------------------------------------------- |
| [src/api.ts](src/api.ts)                     | Calls the API and validates every response at runtime before the page trusts it               |
| [src/App.tsx](src/App.tsx)                   | Page state: readiness, preflight, intro phase, motion, sound, and which renderer is in use    |
| [src/sections](src/sections)                 | Header, hero, marquee, manifesto, method, signal, workbench, ledger, footer                   |
| [src/experience](src/experience)             | Everything decorative: the renderer, shaders, point clouds, scroll mapping, intro, cursor     |
| [src/styles](src/styles)                     | Tokens and base rules, page chrome, and section styles                                        |
| [src/icons.tsx](src/icons.tsx)               | Inline icons; the brand mark is the anvil profile the scene and the static illustration share |
| [public](public)                             | Favicon and the film-grain tile                                                               |
| [../../scripts/probes](../../scripts/probes) | Page scripts for real-GPU measurements through `Capture-Scene.ps1 -Probe`                     |

Inside `src/experience`:

- `engine.ts` is the WebGL2 renderer, written by hand with no 3D library. One
  vertex buffer holds five formations for every ember; the vertex shader blends
  the two formations the page is between. Embers are drawn additively into a
  half-float target where the browser supports one, then bloomed, tone-mapped,
  and composited over smoke.
- `shaders.ts` holds the GLSL. `formations.ts` builds the point clouds (anvil,
  queue, runner pool, field, hammer) from a seeded generator, so they are the
  same on every load.
- `scenes.ts` maps the scroll position to a formation index and to the pair of
  formations being blended. `quality.ts` chooses the quality tier.
- `ForgeCanvas.tsx` loads the engine lazily, feeds it scroll, pointer, heat, and
  strike input, and reports which renderer is in use. `ticker.ts` is the single
  shared animation-frame loop; `bus.ts` carries strike events.
- `Preloader.tsx`, `Cursor.tsx`, `magnet.ts`, and `sound.ts` are the intro
  counter, the trailing pointer ring, the magnetic button, and the synthesised
  strike sound.

## What is real and what is decoration

- Real: the readiness state, schema version, phase, and read time in the signal
  section, and the request and response in the workbench. The page's warm or
  cold look follows that one readiness reading; it is a snapshot taken at page
  load, and the page says so.
- Decoration: every ember formation. Each is captioned as an illustration, and
  the captions for formations appear only while the scene is actually drawn.
  The ember count on the page is the number being drawn at that moment.
- The method cards describe planned modules and are labelled
  `Planned · phase 3 · not built`. No benchmark or performance figure is shown.
- A strike changes the scene, the title, and a counter. It sends nothing to the
  API. A successful preflight triggers one strike at the submit button.
- The sound control reads `on` only once the browser's audio context is running.

## When the scene runs

The plain page is complete on its own. The scene is added only when all of these
hold; otherwise the page shows a static anvil drawing and drifting CSS embers:

- the browser supports `matchMedia` and `IntersectionObserver`;
- a WebGL2 context is available and the first frame reports no GL error;
- the renderer is hardware. Software renderers (SwiftShader, llvmpipe, and
  similar) are refused because they cannot hold a frame rate. Appending
  `?forge=software` to the address opts in for diagnosis and for the browser
  tests, which have no GPU.

A lost WebGL context switches the page to the static art. With the system
reduced-motion preference there is no intro, no pinned section, no flight
between formations (they cross-fade), no cursor ring, and the motion control is
disabled. The motion control stops the scene's drift, the marquee, the kinetic
title, and the CSS animation; scrolling still changes the formation.

The quality governor steps resolution, ember share, and finally bloom down when
frames arrive late, keeps a lower tier only if frames really got quicker, and
tries the tier above again after a calm spell. If no tier is quicker, the cause
is the display or the machine, and the tier it started from is restored.

## Rules that real hardware taught

These came from faults that no software renderer reproduced. Unit tests guard
the first two, and [Capture-Scene.ps1](../../scripts/Capture-Scene.ps1) checks
formation placement on a real GPU.

- Do not index a `mat4` uniform array dynamically in a shader. Direct3D 11, the
  default WebGL backend on Windows, read the wrong element. The application picks
  the two matrices and passes them as separate uniforms.
- Hash the smoke lattice with integers. A float-product hash gave hard-edged
  cells on the GPU.
- Keep the smoke on its small render target. Drawn at full size it was the most
  expensive pass on an integrated GPU.

Details and measurements are in the
[phase ledger](../../docs/PLAN.md#immersive-ui-rebuild).

## Security posture

The Content Security Policy in [nginx.conf](../../infra/docker/nginx.conf) is
unchanged: scripts, styles, fonts, and connections are same-origin only. Fonts
are self-hosted files; Vite's `assetsInlineLimit: 0` keeps them from becoming
data URLs the policy would block. Dynamic styles are set through the CSSOM, not
through style attributes in markup. Server text is rendered as text.

## Tests

- Unit tests (Vitest, jsdom): the API round trip and its failure states, the
  controls, the point clouds, the scroll mapping, the quality governor, and the
  two shader guards.
- Browser tests ([tests/e2e](../../tests/e2e)): the real API and database round
  trip, a cold page when the API is down, layouts from 320 px to 1440 px, a
  short laptop viewport, the controls, reduced motion, a software render of the
  scene with a placement check, the scroll choreography, and a run with WebGL
  disabled.
- The browser tests run without a GPU. Only `Capture-Scene.ps1` shows and checks
  the scene as hardware draws it.
