# Engineering decisions

| ID  | Decision                                                                | Rationale / trade-off                                                                                                                                                                                                                                                       |
| --- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01 | Stop after Phase 1                                                      | The user explicitly limits this iteration; guide prompts for later phases are context, not authorization                                                                                                                                                                    |
| D02 | Java 21, Spring Boot 3.5, React/TypeScript, PostgreSQL                  | Follow the guide's recommended primary stack; no reason to introduce Python application services                                                                                                                                                                            |
| D03 | Containerized Node 22/Maven/Java                                        | Host Node is 14 and Java is absent; do not replace global runtimes or share host package installations                                                                                                                                                                      |
| D04 | `POST /api/preflight` instead of prematurely implementing `POST /jobs`  | Demonstrates validation and a UI/API round trip without introducing Phase 2 job persistence or Phase 3 ingestion                                                                                                                                                            |
| D05 | Single bootstrap metadata migration                                     | Makes real PostgreSQL migration/readiness testable without prematurely designing the domain schema                                                                                                                                                                          |
| D06 | Defer Redis, Kafka, and worker processes                                | No Phase 1 workload needs short-lived distributed state or asynchronous events; avoids unjustified services and resource use                                                                                                                                                |
| D07 | Static OpenAPI with generated frontend types                            | Explicit, reviewable contract without an additional runtime documentation framework; tests protect the Java implementation                                                                                                                                                  |
| D08 | Same-origin Nginx proxy                                                 | Avoid broad CORS rules and do not expose the DB; direct API access remains loopback-only for development                                                                                                                                                                    |
| D09 | Generated local secret files, not sample passwords                      | No secrets in source or logs; files are reused rather than silently rotated                                                                                                                                                                                                 |
| D10 | Separate ephemeral PostgreSQL for integration tests                     | Real SQL/Flyway coverage without touching the local application database or mounting the Docker socket                                                                                                                                                                      |
| D11 | Local OpenTelemetry context, no exporter                                | Follow the observability direction without adding a collector or sending data off the machine                                                                                                                                                                               |
| D12 | Existing monorepo directory without `.git` initialization               | Git is not needed to build/test, and this project has no initialization approval; CI is authored but not published                                                                                                                                                          |
| D13 | Fixed loopback ports 18102/18202 and Compose project `blacksmith`       | Respect concurrent-project isolation; port conflicts fail explicitly rather than selecting another project's port                                                                                                                                                           |
| D14 | Bounded sequential build/check workflow                                 | Limit pressure while ten project sessions may be active; keep normal runtime footprint below 1 GiB of configured memory                                                                                                                                                     |
| D15 | Project-scoped Docker volumes for generated dependency trees and caches | Initial Windows bind-mounted npm restore reported two hours and Maven formatting took 49:58; a registry-only React download took 1.108 seconds. Remove bind-mount dependency I/O from the normal workflow without changing host runtimes or sharing another project's cache |

These decisions can be revised only with evidence and within the approved scope.
No alternative implementation is silently substituted after a failure.
