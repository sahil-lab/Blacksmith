# Engineering decisions

| ID  | Decision                                                                | Rationale / trade-off                                                                                                                                                                                                                                                       |
| --- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01 | Stop after Phase 1                                                      | The user explicitly limits this iteration; guide prompts for later phases are context, not authorization                                                                                                                                                                    |
| D02 | Java 21, Spring Boot 3.5, React/TypeScript, PostgreSQL                  | Follow the guide's recommended primary stack; no reason to introduce Python application services                                                                                                                                                                            |
| D03 | Containerized Node 22/Maven/Java                                        | Host Node is 14 and Java is absent; do not replace global runtimes or share host package installations                                                                                                                                                                      |
| D04 | `POST /api/preflight` instead of prematurely implementing `POST /jobs`  | Demonstrates validation and a UI/API round trip without introducing Phase 2 job persistence or Phase 3 ingestion                                                                                                                                                            |
| D05 | Single bootstrap metadata migration                                     | Makes real PostgreSQL migration/readiness testable without prematurely designing the domain schema                                                                                                                                                                          |
| D06 | Defer Redis, Kafka, and worker processes                                | No Phase 1 workload needs short-lived distributed state or asynchronous events; avoids unjustified services and resource use                                                                                                                                                |
| D07 | Static OpenAPI with generated frontend types                            | Explicit, reviewable contract without an additional runtime documentation framework; tests protect the Java implementation                                                                                                                                                  |
| D08 | Same-origin Nginx proxy                                                 | Avoid broad CORS rules and do not expose the DB; direct API access remains loopback-only for development                                                                                                                                                                    |
| D09 | Generated local secret files, not sample passwords                      | No secrets in source or logs; files are reused rather than silently rotated                                                                                                                                                                                                 |
| D10 | Separate ephemeral PostgreSQL for integration tests                     | Real SQL/Flyway coverage without touching the local application database or mounting the Docker socket                                                                                                                                                                      |
| D11 | Local OpenTelemetry context, no exporter                                | Follow the observability direction without adding a collector or sending data off the machine                                                                                                                                                                               |
| D12 | No Git writes by this work                                              | Git is not needed to build or test, and no approval was given for initialization, commits, remotes, or pushes. The directory was later found to be a repository with a pushed remote, set up outside this work (see the [phase ledger](PLAN.md#repository-state-observed-on-2026-11-13)); the rule is unchanged |
| D13 | Fixed loopback ports 18102/18202 and Compose project `blacksmith`       | Respect concurrent-project isolation; port conflicts fail explicitly rather than selecting another project's port                                                                                                                                                           |
| D14 | Bounded sequential build/check workflow                                 | Limit pressure while ten project sessions may be active; keep normal runtime footprint below 1 GiB of configured memory                                                                                                                                                     |
| D15 | Project-scoped Docker volumes for generated dependency trees and caches | Initial Windows bind-mounted npm restore reported two hours and Maven formatting took 49:58; a registry-only React download took 1.108 seconds. Remove bind-mount dependency I/O from the normal workflow without changing host runtimes or sharing another project's cache |

These decisions can be revised only with evidence and within the approved scope.
No alternative implementation is silently substituted after a failure.

## Front-end decisions

Made during the immersive rebuild. Measurements and commands are in the
[phase ledger](PLAN.md#immersive-ui-rebuild).

| ID  | Decision                                                                    | Rationale / trade-off                                                                                                                                                                                                                                                                             |
| --- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D16 | Hand-written WebGL2 renderer, no 3D library                                 | The scene is one point cloud, a spark buffer, and a handful of full-screen passes. A general 3D library would be a large dependency to ship and audit for that. The cost is owning the GL code and its driver quirks, which D18 and D19 exist to contain                                          |
| D17 | The scene is an enhancement; software renderers are refused                 | The plain page is complete without it. In the GPU-less test container the software renderer was slow enough to time the browser tests out, so the engine falls back to static art there. `?forge=software` opts in for diagnosis and for one deliberately small browser test                      |
| D18 | No dynamically indexed `mat4` uniform arrays; integer lattice hash          | Direct3D 11 read the wrong element of such an array, drawing every formation with the wrong placement, and a float-product hash gave hard-edged smoke. Neither fault appeared on any software renderer. Unit tests keep both constructs out of the shaders                                        |
| D19 | An optional real-GPU capture script, outside `Verify.ps1` and CI            | Hosted and containerised browsers have no GPU, and D18's faults were visible only on hardware. The script is Windows-only and needs an installed Edge or Chrome, so it cannot be a required gate. Scene changes are checked with it by hand                                                       |
| D20 | A quality governor that verifies every step                                 | Frame times cannot tell a slow GPU from a busy machine or one heavy moment. The first sampler only ever stepped down, so a scripted scroll through the page on the development laptop ended at the lowest tier although full quality could hold the display rate at rest. Now a lower tier is kept only if frames got quicker, is retried upward after a calm spell, and is undone when no tier helps |
| D21 | The smoke is drawn at a quarter of the resolution on its own target         | Measured as the most expensive pass on the integrated GPU. The smoke is low-frequency, the captures show no visible difference after stretching it back, and film grain is still added per pixel afterwards                                                                                       |
| D22 | Decoration never claims to be data                                          | Formation captions appear only while the scene is drawn, the ember count is the number drawn, the sound control reads `on` only when audio runs, and nothing decorative is derived from job or runner data. The honesty rule of the skeleton applies to the art as well                           |
| D23 | An anvil brand mark and a hammer as the closing formation                   | The earlier four-square tile mark, drawn large in embers, read as another company's logo. Both shapes now come from this project's own forge vocabulary, and the mark, the favicon, the scene, and the static illustration share one anvil outline                                                |
| D24 | Synthesised strike sound, off by default                                    | No audio file to host or license, and no Content Security Policy change. Browsers require a user gesture before audio, and unrequested sound is unwelcome, so the visitor has to switch it on                                                                                                     |

## Shared-host network exhaustion

The first normal-stack start failed because Docker's predefined address pools
were fully allocated. Existing Docker CIDRs and host routes were inspected
read-only. The two new Blacksmith runtime networks use unoccupied local-lab
subnets `198.18.102.0/28` (frontend) and `198.18.102.16/28` (internal data).
These non-Internet-routed lab addresses avoid the host's private/VPN routes.
Existing check networks were retained unchanged; no network was removed and no
Docker daemon configuration or another project's resources were changed.
